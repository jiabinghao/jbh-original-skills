# 视频构建流程

帮助用户得到可播放且符合规格的视频。此技能提供工作流程，不包含渲染器、媒体素材或 HyperFrames 的第三方实现。

## 确认项目与环境

确定输出时长、尺寸、帧率、音频需求和交付路径；缺省值明确标注，并服从用户指定规格。已有项目先检查依赖清单、锁文件、入口和素材路径。使用项目已安装的 CLI；初始化新项目或命令不明确时读取 [CLI 核对与排错](references/cli-workflow.md)，查对应版本的帮助和官方文档。不要把最新文档的参数强套到旧版本。

检查 Node.js、FFmpeg 与渲染所需浏览器的实际可用状态。缺依赖时按任务范围安装或提供精确阻塞原因，不把生成了 HTML 当作生成了视频。只使用用户有权使用的音频、图片、字体与视频；缺素材时可采用自制图形或说明占位内容。

## 建立能按时间定位的画面

将镜头组织为明确时间区间，确保字幕、媒体、动画和声音在同一时间位置可重现。等待字体和素材加载后再采集画面。避免依赖随机数、实时请求或播放开始以来的累积状态；确需这些数据时先固定输入，并说明可复现范围。

先预览和检查，再渲染。在镜头起点、转场前后、文字密集处与结束前检查采样帧；数量取决于实际镜头，不固定只看三张图。修正遮挡、字幕越界、缺图和时间轴空白；音视频项目还应实际听看对应片段。

## 渲染与核验

使用当前 CLI 支持的输出参数，写入明确的目标文件；已有成片需保留时选择新路径。记录命令、版本和执行状态。命令失败或超时后先查输出及进程状态，避免把旧成片误认为本次结果。

成功退出后检查文件可读取、媒体流、时长、尺寸和帧率。用可用播放器检查开头、转场与结尾；需要音频时确认存在音轨并听取代表片段。若有 FFmpeg 工具，可辅助进行媒体探测和解码检查，但技术参数通过不能替代视觉和听觉检查。

修改画面或声音后重新渲染受影响成片，并确认核验对象为最新文件。交付视频路径、简短规格与验证限制；没有播放器或采样工具时明确未完成的检查。公开上传、云端发布或调用收费媒体服务仅在用户任务已授权时执行。
