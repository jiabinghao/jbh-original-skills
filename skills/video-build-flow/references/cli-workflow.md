# CLI 核对与排错

初始化、命令选型或渲染失败时使用本记录。它是维护者独立整理的决策提示，不是第三方手册副本。官方资料可能变化，以项目使用版本的帮助为准。

## 查证入口

- [官方 CLI 文档](https://github.com/heygen-com/hyperframes/blob/main/docs/developers/cli.mdx)：核对当前子命令与参数。
- [官方项目](https://github.com/heygen-com/hyperframes)：核对安装方式、运行要求和工具许可。
- [HeyGen 环境说明](https://help.heygen.com/en/articles/15001510-hyperframes-x-heygen)：2026-10-05 查阅时说明 Node.js 22+ 与 FFmpeg 前提；以后应重新核对。

命令示意仅用于定位能力。`npx` 在本地无包时可能下载依赖，执行前检查项目已有依赖；有锁定版本时使用项目配置的运行方式。需要安装时固定经查证的版本，不因示例而默认升级。

```text
node --version
ffmpeg -version
npx hyperframes --help
npx hyperframes <subcommand> --help
```

## 根据证据选择动作

| 当前状态 | 应核对的命令 | 完成依据 |
| --- | --- | --- |
| 无项目入口 | init | 新项目目录与入口真实存在，命令参数已确认 |
| 有入口但画面不确定 | preview | 页面加载完成、目标时间位置可观察 |
| 项目或时间轴疑似不完整 | lint、check | 真实诊断已读取，影响渲染的问题已处理 |
| 想定位具体画面错误 | snapshot | 对照时间轴选取时间点，确认采样帧与当前内容一致 |
| 已具备渲染条件 | render | 当前输出可解码且规格、关键片段核验完成 |
| 环境本身无法启动 | doctor | 按诊断确认缺项，修复后重跑失败步骤 |

先用帮助核对具体选项，不能把上表当作保证所有版本都有同名命令的承诺。需要网络、浏览器或编码器时，以实际诊断判断依赖，不循环重装。

路径错误先检查工作目录、相对路径、大小写和资源是否存在；画面错误先区分素材加载与时间定位；输出错误先区分渲染、编码和播放。命令完成但画面仍错误时返回内容层排查，不能只重复渲染。`publish` 涉及外部发布，生成本地视频无需执行。
