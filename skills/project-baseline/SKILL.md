# 项目协作基线

让后续工作能找到正确入口、执行真实检查并理解任务存放方式。默认中文写文档，沿用已有工具和约定。

## 先盘点已有约定

读取项目指引、README、包管理配置、CI 文件和任务目录。确认运行环境、安装方式、启动命令、测试入口及分支状态。只在必要时运行版本命令，不在输出中收集环境变量值或凭据。

从当前事实提取基线：应用入口、关键目录、权威检查命令、需要的环境变量名称和现有议题管理方式。无法确认的命令标成待验证，不编造标准脚本。

## 补齐最小缺口

优先修订现有说明；若没有合适位置，再创建简短的项目入口文档。只记录后续工作需要而不容易推断的信息。不要把一次任务的偏好写成全项目永久规则。

项目已有 GitHub Issues、其他跟踪器或本地 Markdown 时沿用它。只有用户明确要求才创建远程标签、项目或自动化。缺少跟踪方式时可给出本地方案，不让第三方账号成为开始工作的前提。

检查配置变动是否会覆盖现有设置、触发 CI 或上传信息；依赖安装和版本调整必须服务于当前任务。密钥示例只列变量名和用途，不复制真实值。

## 验证和交付

执行适合当前环境的安装、启动或检查步骤，并记录真实结果。资源消耗较大或会访问生产服务的命令，先确定是否在用户范围内。无法运行时保留精确阻碍及后续检查动作。

交付入口文件链接、可执行命令、任务记录位置及尚未确认的配置。不要用增加大量规范文件的方式替代实际环境验证。
