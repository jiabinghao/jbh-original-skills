# 14 个技能的中文说明

默认使用中文沟通，代码、命令与专有名称沿用原文。运行时需要代理自身具备相应工具；缺少工具时应交付未完成项与精确限制。

## 1. 技能选型助手 · skill-scout

- **用途**：选择匹配任务的工具。
- **何时使用**：根据任务与环境筛选适合的技能，核对依赖许可并说明推荐理由。
- **建议提供**：期望交付物、代理平台、操作系统、已安装工具和可接受的依赖成本。
- **预期输出**：候选对比、来源、限制与试用请求。
- **边界**：需要检索或读取技能目录的工具；并不自带搜索服务。
- **技能文件**：[SKILL.md](../skills/skill-scout/SKILL.md)。

示例请求：

> 请用 $skill-scout 为 Windows 上的 Codex 筛选一个适合批量整理 PDF 的技能。

判断是否有用：推荐理由与实际环境相符，来源可查，许可不明确的候选已标注，安装状态没有夸大。

## 2. 方案压力测试 · plan-probe

- **用途**：检查关键决策假设。
- **何时使用**：检查方案关键假设与验证成本，形成可执行且可判断的下一步。
- **建议提供**：现有方案、目标用户、时间与预算约束、成功标准。
- **预期输出**：证据与假设清单、条件结论、低成本验证动作。
- **边界**：评估不代表自动投资、联络客户或发布产品。
- **技能文件**：[SKILL.md](../skills/plan-probe/SKILL.md)。

示例请求：

> 请用 $plan-probe 评估我两周内上线一个知识付费小产品的方案。

判断是否有用：最重要的假设被指出，并给出能改变决定的验证动作，而不是一长串泛泛问题。

## 3. 项目上下文核对 · context-check

- **用途**：让方案与项目事实对应。
- **何时使用**：核对方案文档与代码中的业务规则，定位冲突并形成修订建议。
- **建议提供**：拟议变更、相关业务文档、代码位置和需要核对的版本。
- **预期输出**：冲突证据、行为说明、文档修订和待决问题。
- **边界**：需要可访问的项目材料；没有代码时仅核对文档。
- **技能文件**：[SKILL.md](../skills/context-check/SKILL.md)。

示例请求：

> 请用 $context-check 检查这份退款方案与现有文档和代码是否一致。

判断是否有用：每个重要冲突有对应证据，当前实现与设计意图分开，待决事项没有被伪装成已批准。

## 4. 浏览器任务执行 · browser-workflow

- **用途**：执行并核验网页操作。
- **何时使用**：通过已有浏览器工具执行网页任务，逐步核验保存后的真实结果。
- **建议提供**：目标网站、具体对象、最终状态；登录凭据在网站正常登录流程中自行处理。
- **预期输出**：来源链接、实际操作结果及必要的证据截图。
- **边界**：仅提供流程指令，不提供 agent-browser CLI 或浏览器驱动。
- **技能文件**：[SKILL.md](../skills/browser-workflow/SKILL.md)。

示例请求：

> 请用 $browser-workflow 在指定网站整理三款产品的公开参数和来源。

判断是否有用：目标页面的保存后状态已核验；若提交状态不确定，明确指出并避免重复创建对象。

## 5. 架构局部改进 · architecture-tune

- **用途**：降低具体维护成本。
- **何时使用**：从实际维护困难定位耦合边界，完成最小重构并验证行为兼容。
- **建议提供**：维护困难的例子、相关代码和需要保持的对外行为。
- **预期输出**：局部重构、兼容说明、行为验证与剩余代价。
- **边界**：需要代码与检查工具；并非自动重写全项目。
- **技能文件**：[SKILL.md](../skills/architecture-tune/SKILL.md)。

示例请求：

> 请用 $architecture-tune 改善这段订单代码的重复校验并保持现有行为。

判断是否有用：原维护困难得到具体缓解，必要行为保护和调用者迁移已经验证。

## 6. 行为测试先行 · behavior-tests

- **用途**：让测试证明业务行为。
- **何时使用**：围绕用户行为编写失败测试，完成实现并留下真实的回归验证记录。
- **建议提供**：需求或缺陷复现、期望结果、项目代码和测试入口。
- **预期输出**：失败原因、测试用例、实现与实际执行结果。
- **边界**：需要项目测试运行器；文件存在不代表测试已经通过。
- **技能文件**：[SKILL.md](../skills/behavior-tests/SKILL.md)。

示例请求：

> 请用 $behavior-tests 为优惠券到期后仍可使用的问题添加回归测试并修复。

判断是否有用：失败确实源自目标行为，修复后的同一用例通过，执行状态和未覆盖边界真实记录。

## 7. 界面设计与实现 · interface-craft

- **用途**：设计可使用的网页。
- **何时使用**：围绕用户任务实现响应式界面，覆盖完整交互状态并检查关键路径。
- **建议提供**：页面目标、用户路径、视觉规范或参考方向、现有技术栈。
- **预期输出**：可运行页面、交互状态、预览方式与验证说明。
- **边界**：需要开发工具；浏览器不可用时会标出视觉检查限制。
- **技能文件**：[SKILL.md](../skills/interface-craft/SKILL.md)。

示例请求：

> 请用 $interface-craft 制作中文读书记录页面，支持新增、筛选和空状态。

判断是否有用：核心交互能够运行，空数据和错误状态已处理，预览和未实测的范围清楚。

## 8. 项目协作基线 · project-baseline

- **用途**：让项目能被正确接手。
- **何时使用**：盘点仓库约定和检查入口，补齐能够支持后续协作的最小文档。
- **建议提供**：仓库路径、当前环境、协作方式及需要补齐的说明。
- **预期输出**：入口说明、真实命令、任务记录位置与配置缺口。
- **边界**：不依赖任何指定作者的技能包；远程配置按用户授权执行。
- **技能文件**：[SKILL.md](../skills/project-baseline/SKILL.md)。

示例请求：

> 请用 $project-baseline 接手这个仓库并补齐启动、测试和任务记录说明。

判断是否有用：接手者可以找到入口、运行真实命令并知道任务记录位置，文档没有凭空生成规则。

## 9. 工作续接说明 · work-handoff

- **用途**：保存接续任务所需状态。
- **何时使用**：将当前目标、已完成工作与剩余依赖整理成可核实的任务交接材料。
- **建议提供**：当前任务上下文、工作文件、保存位置和下一阶段目标。
- **预期输出**：版本定位、验证记录、剩余任务和第一项行动。
- **边界**：生成材料不会自动创建聊天、发送消息或转交外部权限。
- **技能文件**：[SKILL.md](../skills/work-handoff/SKILL.md)。

示例请求：

> 请用 $work-handoff 把当前任务保存为项目中的交接文档，方便下次继续。

判断是否有用：接手者无需重读完整对话即可定位当前工作，并执行第一项有明确结果的待办。

## 10. 问题与需求分流 · issue-sort

- **用途**：把报告变成可执行任务。
- **何时使用**：依据影响和证据整理错误报告与功能请求，给出优先级和就绪判断。
- **建议提供**：原始报告、项目优先级标准、关联议题和能够提供的复现证据。
- **预期输出**：去重关联、优先级、就绪状态与下一步。
- **边界**：默认提供整理报告；远程修改需要在用户请求范围内。
- **技能文件**：[SKILL.md](../skills/issue-sort/SKILL.md)。

示例请求：

> 请用 $issue-sort 整理这些问题报告，给出优先级、缺失信息和验收条件。

判断是否有用：严重程度与可实施程度分开，每项有理由与下一步，重复判断有证据。

## 11. 原型验证 · prototype-lab

- **用途**：以最少实现取得能回答关键未知的证据。
- **何时使用**：验证产品交互、技术可行性或数据处理路径。
- **建议提供**：待验证的问题、技术栈、实验目录、资源上限和成功条件。
- **预期输出**：可运行原型、启动命令、实际观测、替代项和继续条件。
- **边界**：模拟接口不能证明真实集成；可运行演示不等于生产就绪。
- **技能文件**：[SKILL.md](../skills/prototype-lab/SKILL.md)。

示例请求：

> 请用 $prototype-lab 制作本地文件筛选原型，验证用户能否在一分钟内找到目标文件。

判断是否有用：原型确实执行了待验证路径；证据支持、否定或不足的结论清楚，下一次投入有触发条件。

## 12. 决策依赖审查 · decision-map

- **用途**：找出多个选择之间的条件关系，决定先验证什么、再承诺什么。
- **何时使用**：技术选型或产品方案中，一个选择会限制另一个选择。
- **建议提供**：候选方案、硬性约束、已知证据、成本与可撤回程度。
- **预期输出**：依赖表或简单图、分支比较、条件推荐、决策记录和下一步。
- **边界**：重点是多项决策的关系；plan-probe 重点是单个方案的假设，不要求重复使用两项技能。不会自动采购或迁移。
- **技能文件**：[SKILL.md](../skills/decision-map/SKILL.md)。

示例请求：

> 请用 $decision-map 比较本地与托管部署，梳理数据位置、运维能力和服务选型之间的依赖。

判断是否有用：推荐解释了依赖原因，写明何种事实会改变选择，取证顺序先于难以撤回的承诺。

## 13. 视频构建流程 · video-build-flow

- **用途**：将 HTML 视频项目通过现有 HyperFrames CLI 输出为可核验的成片。
- **何时使用**：项目初始化、画面时间轴排查、预览和本地视频渲染。
- **建议提供**：项目目录、素材权限、时长、尺寸、帧率、音频需求和输出路径。
- **预期输出**：视频文件、执行与环境记录、规格及关键片段的核验结果。
- **边界**：依赖外部 CLI、Node.js、FFmpeg 和渲染环境；本技能不包含这些实现，也不自动上传视频。第三方软件和素材使用其各自许可。
- **技能文件**：[SKILL.md](../skills/video-build-flow/SKILL.md)。

示例请求：

> 请用 $video-build-flow 把现有 HTML 视频项目渲染为 30 秒的 1080p MP4，并检查转场和音轨。

判断是否有用：核验对象是最新成片，媒体规格和画面声音分别检查，工具限制与未完成检查如实说明。

## 14. React 性能改进 · react-perf-tune

定位 React 与 Next.js 的实际性能瓶颈，完成局部优化并比较相同场景的前后结果。

- **建议输入**：代码目录、依赖版本、变慢的操作、数据量与测量环境。
- **预期输出**：瓶颈证据、改动文件、相同口径的前后结果和剩余问题。
- **能力边界**：需要代码和测量工具；静态分析不能承诺提速百分比，不自动升级框架。
- **完成依据**：优化针对真实瓶颈，交互行为保持正确，指标带有构建模式和测量条件。

### 调用示例

> 请用 $react-perf-tune 排查这个 React 搜索页输入卡顿的问题，并用同一数据量比较优化前后的表现。

使用前需要代理平台具备任务相应的文件、开发、浏览器或媒体工具；缺少工具时应说明未完成项。这是独立编写的指令包，不附带参考技能的软件实现。
